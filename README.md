# Локальный анализ телефонных разговоров

Проект локально расшифровывает аудиозапись разговора, определяет смену говорящих и сохраняет результат в Excel.

Готовая таблица содержит три колонки:

| Таймлайн | Собеседник | Что сказано |
| --- | --- | --- |
| `00:06.000-00:10.980` | `Собеседник А` | Текст реплики |

После установки моделей анализ выполняется полностью локально: аудиозапись и распознанный текст не отправляются по HTTPS и не передаются во внешние API.

## Возможности

- распознавание русской речи с помощью `faster-whisper`;
- разделение разговора на собеседников с помощью `sherpa-onnx`;
- автоматические метки `Собеседник А`, `Собеседник Б`, `Собеседник В` и далее;
- временные границы каждой реплики;
- сохранение результата в формат `.xlsx`;
- настройка точности, диаризации и защитных ограничений через JSON;
- нормализованная привязка слов к перекрывающимся голосовым интервалам, чтобы короткий ответ не поглощался длинной репликой;
- автоматическое создание `voice settings.json`, если файла ещё нет.

## Состав проекта

| Файл или папка | Назначение |
| --- | --- |

| `voice settings.json` | Настройки анализа. Автоматически создаётся при первом запуске, если отсутствует. |

| `requirements.txt` | Python-зависимости проекта. |
| `models/` | Локальные веса моделей. Не сохраняются в Git по умолчанию. |

| `voice example.wav` | Тестовая запись для примера запуска. |

## Системные требования

- 64-битный Python 3.9 или новее;
- около 550 МБ свободного места для моделей, а также место для Python-окружения;
- CPU достаточно, видеокарта NVIDIA не обязательна;
- интернет нужен только для первоначальной загрузки Python-библиотек и весов моделей.

Проверенная конфигурация: Windows, Python 3.12.13, обработка на CPU с `int8`.

## Быстрый старт на Windows

### 1. Создайте виртуальное окружение

```powershell
python -m venv .venv
```

### 2. Установите библиотеки

```powershell
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Устанавливаются:

- `faster-whisper` — распознавание речи;
- `sherpa-onnx` — разделение голосов;
- `openpyxl` — создание Excel-файла.

### 3. Один раз скачайте локальные модели

```powershell
.\.venv\Scripts\python.exe download_models.py
```

Команда использует интернет только для загрузки весов в папку `models/`. После этого функция `analyze_call(...)` работает офлайн.

Папка `models/` исключена из Git из-за размера. Поэтому команду необходимо выполнить на каждом новом компьютере либо передать готовую папку `models/` вместе с проектом.

### 4. Запустите готовый пример

Убедитесь, что в папке проекта находится `voice example.wav`, затем выполните:

```powershell
.\.venv\Scripts\python.exe "start example.py"
```

Результат появится рядом с исходной записью:

```text
voice example transcript.xlsx
```

## Как использовать в своём Python-проекте

Основная точка входа:

```python
analyze_call(filename: str) -> pathlib.Path
```

Аргумент `filename` — абсолютный или относительный путь к аудиофайлу. Функция возвращает абсолютный путь к созданному Excel-файлу.

Поскольку текущее имя `voice description.py` содержит пробел, модуль загружается через `importlib`. Готовый вариант уже находится в `start example.py`:

```python
import importlib.util
import sys
from pathlib import Path


def load_analyzer():
    script = Path(__file__).resolve().parent / "voice description.py"
    spec = importlib.util.spec_from_file_location("voice_description", script)
    if spec is None or spec.loader is None:
        raise ImportError(f"Не удалось загрузить модуль: {script}")

    module = importlib.util.module_from_spec(spec)
    sys.modules[spec.name] = module
    spec.loader.exec_module(module)
    return module


analyzer = load_analyzer()
excel_path = analyzer.analyze_call(r"C:\records\call.wav")
print(excel_path)
```

Также можно вызвать основной файл из командной строки:

```powershell
.\.venv\Scripts\python.exe "voice description.py" "C:\records\call.wav"
```

## Встраивание в существующий проект

Минимально перенесите в отдельную папку внутри своего проекта:

```text
your-project/
|-- voice-analysis/
|   |-- voice description.py
|   |-- download_models.py
|   |-- requirements.txt
|   `-- models/
`-- your_application.py
```

Далее:

1. Установите зависимости из `requirements.txt` в окружение основного проекта.
2. Запустите `download_models.py` из папки `voice-analysis` или скопируйте туда готовую папку `models`.
3. Загрузите `voice description.py` через `importlib`, как показано выше.
4. Передайте путь к записи в `analyze_call(...)`.
5. Используйте возвращённый `Path` для дальнейшей работы с Excel-файлом.

`voice settings.json` переносить необязательно. При первом вызове функции он будет создан рядом с `voice description.py`. Каталог модуля должен быть доступен приложению для записи.

## Настройки

При каждом вызове `analyze_call(...)` файл `voice settings.json` читается заново. Поэтому для применения изменений не требуется переустанавливать проект.

Порядок приоритетов:

1. встроенные значения используются как шаблон;
2. значения из `voice settings.json` заменяют встроенные значения;
3. явно заданная переменная окружения `VOICE_NUM_SPEAKERS` заменяет только `diarization.num_speakers`.

Основные настройки:

| Параметр | По умолчанию | Назначение |
| --- | ---: | --- |
| `limits.max_file_size_mb` | `0` | Максимальный размер файла в МиБ. `0` отключает лимит. |
| `limits.max_duration_minutes` | `0` | Максимальная длительность в минутах. `0` отключает лимит. |
| `recognition.language` | `"ru"` | Язык записи. |
| `recognition.device` | `"cpu"` | Устройство вычислений. Для совместимой NVIDIA можно использовать `"cuda"`. |
| `recognition.compute_type` | `"int8"` | Экономичный режим для CPU. |
| `recognition.cpu_threads` | `0` | Автоматический выбор до 8 потоков. |
| `recognition.beam_size` | `5` | Ширина поиска. На example увеличение до `10` добавило ошибочные фразы, поэтому оставлено `5`. |
| `recognition.temperature` | `0.0` | Стабильное распознавание без дополнительной вариативности. |
| `recognition.condition_on_previous_text` | `true` | Сохраняет контекст между фрагментами. |
| `recognition.vad_filter` | `true` | Удаление участков без речи перед распознаванием. |
| `recognition.vad_min_silence_duration_ms` | `200` | Минимальная пауза VAD. Значение подобрано для коротких телефонных реплик. |
| `recognition.initial_prompt` | `""` | Контекст: тема, вероятные имена, адреса и термины. |
| `recognition.hotwords` | `""` | Важные имена и слова, которым следует дать больший вес. |
| `diarization.num_speakers` | `-1` | Автоопределение. На коротком mono-example принудительные `2` схлопнули результат в один голос. |
| `diarization.cluster_threshold` | `0.55` | Порог разделения голосов в автоматическом режиме. |
| `diarization.window_shift_ratio` | `0.1` | Шаг окна диаризации. `0.05` не улучшил example и заметно замедлил обработку. |
| `diarization.min_duration_on` | `0.3` | Минимальная длительность речевого фрагмента. |
| `diarization.min_duration_off` | `0.5` | Заполнение коротких разрывов внутри речи. |
| `postprocessing.merge_max_gap_seconds` | `0.45` | Максимальная пауза для объединения слов одного голоса. Небольшое значение не даёт склеивать короткие реплики. |

Полный список параметров и рекомендации по их подбору приведены в `voice description instruction.pdf`.

## Поддерживаемые аудиоформаты

`WAV`, `MP3`, `M4A`, `MP4`, `MPEG`, `MPGA`, `OGG`, `FLAC`, `WEBM`.

Стерео и многоканальные записи автоматически сводятся в mono 16 кГц.

## Ограничения размера и длительности

По умолчанию жёсткого ограничения в мегабайтах или минутах нет. Практический предел определяется оперативной памятью и временем обработки.

- декодированный массив занимает примерно 230 МБ на час записи;
- дополнительная память требуется моделям и промежуточным данным;
- текущая реализация хранит декодированную запись целиком в RAM;
- для компьютера с 8 ГБ RAM разумно начинать с записей длительностью до 60-120 минут и контролировать потребление памяти.

Для защиты приложения задайте, например:

```json
{
  "limits": {
    "max_file_size_mb": 500,
    "max_duration_minutes": 120
  }
}
```

Остальные отсутствующие поля будут взяты из встроенных значений по умолчанию.

## Повышение точности

- оставьте `diarization.num_speakers: -1` для коротких mono-записей и сначала оцените автоопределение;
- точное число участников задавайте для более длинных записей, где каждый человек говорит достаточно долго, и обязательно сравнивайте с `-1`;
- добавьте вероятные имена, адреса и специальные термины в `initial_prompt` и `hotwords`;
- при шумной речи можно сравнить `beam_size: 7` со значением `5`, но увеличение иногда добавляет выдуманный текст;
- если определяется слишком много голосов, немного увеличьте `cluster_threshold`;
- если разные голоса ошибочно объединяются, немного уменьшите `cluster_threshold`;
- не уменьшайте `window_shift_ratio` без проверки времени: на example значение `0.05` не улучшило разделение, но заметно замедлило его;
- изменяйте параметры постепенно и сравнивайте результат на одном и том же файле.

## Частые проблемы

### Не найдены локальные модели

Выполните:

```powershell
.\.venv\Scripts\python.exe download_models.py
```

Либо поместите готовую папку `models/` рядом с `voice description.py`.

### Не установлена библиотека

Убедитесь, что установка и запуск выполняются одним и тем же Python:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe "start example.py"
```

### Ошибка JSON

JSON не поддерживает комментарии и завершающие запятые. Проверьте синтаксис и имена полей. Если удалить файл `voice settings.json`, при следующем запуске будет создан новый файл со стандартными значениями.

### Неверно определяется число собеседников

Для известного количества участников задайте точное значение, например:

```json
{
  "diarization": {
    "num_speakers": 2
  }
}
```

## Конфиденциальность

После загрузки моделей распознавание, разделение голосов и формирование Excel выполняются на локальном компьютере. Для анализа аудио сетевые запросы не используются.

Перед передачей результата другим системам самостоятельно проверьте требования к хранению персональных данных и телефонных разговоров.
